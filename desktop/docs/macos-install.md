# Установка на macOS и подключение TUN

Эта сборка распространяется без сертификата Apple Developer ID и без notarization.
Внутренняя **ad-hoc подпись** нужна для корректного запуска исполняемых файлов,
в частности на Apple Silicon; она не подтверждает личность разработчика для macOS.
Apple Developer Program пользователю не нужен. Для установки системной службы TUN
понадобится пароль администратора Mac.

## Установка приложения

1. Скачайте DMG из [официальных релизов CheezyClash](https://github.com/l0nelynx/CheezyClash/releases).
   Для Mac с Apple M1/M2/M3 и более новыми чипами Apple выбирайте **arm64**;
   для Intel — **x64**. Тип процессора указан в меню Apple → «Об этом Mac».
2. Откройте DMG и перетащите **CheezyClash.app** в **«Программы» (/Applications)**.
   Закройте приложение, если открывали его прямо из DMG; затем запустите копию из «Программ».
3. Если macOS сообщает, что разработчика нельзя проверить, закройте предупреждение.
   Откройте **Системные настройки → Конфиденциальность и безопасность**, найдите
   сообщение о блокировке CheezyClash и нажмите **«Всё равно открыть»** (Open Anyway).
   Подтвердите открытие. На разных версиях macOS название кнопки может отличаться.
4. Откройте приложение и добавьте подписку или профиль.

Это разрешение на запуск приложения. Запрос установки службы TUN — отдельный шаг.
Официальная инструкция Apple: [как открыть приложение от непроверенного разработчика](https://support.apple.com/102445).

### Если «Всё равно открыть» не помогло

Сначала повторно скачайте нужную сборку из официального релиза. Если к релизу
приложены контрольные суммы, сравните сумму загруженного файла. Сообщение
«приложение повреждено» может означать и повреждённую загрузку, а не только карантин.

Если вы проверили происхождение загрузки, а macOS продолжает блокировать именно
эту неподписанную сборку, закройте приложение и выполните в «Терминале»:

```sh
xattr -dr com.apple.quarantine "/Applications/CheezyClash.app"
```

Команда снимает метку карантина только с указанного приложения. Она не исправляет
повреждённый файл. Если получен `Permission denied`, для этой же команды может
потребоваться `sudo` и пароль администратора:

```sh
sudo xattr -dr com.apple.quarantine "/Applications/CheezyClash.app"
```

После этого запустите приложение из «Программ». Отключать Gatekeeper для всего Mac,
SIP или firewall не требуется. Не применяйте эти команды к другим каталогам.
Если macOS прямо сообщает об обнаружении вредоносного ПО, не обходите эту блокировку.

Для сборки CheezyVPN действия те же; используйте имя `CheezyVPN.app` и официальный
источник этой сборки. Не переименовывайте приложение ради выполнения команды.

## Первое подключение TUN

1. Активируйте профиль. Если режим задаёт подписка через YAML, будет использован
   её режим. Чтобы выбрать TUN самостоятельно, откройте **Настройки → Подключение**,
   включите переопределение сетевых настроек YAML и выберите **TUN**.
2. На главной странице нажмите **«Подключить»**.
3. Прочитайте сообщение об установке системной службы и нажмите **«Продолжить»**.
4. В системном диалоге macOS введите пароль администратора. Диалог может упоминать
   `osascript`: приложение использует системный механизм авторизации установки.
   Пароль вводится в диалог macOS; клиент его не получает и не сохраняет.
5. Дождитесь завершения настройки. Подключение продолжится автоматически.
   После успешного запуска отображается режим **TUN**.

На последующих подключениях повторная установка не нужна. Если обновились ядро
или служба, macOS снова запросит разрешение на обновление защищённых файлов.
После перезагрузки служба доступна, но сама по себе VPN не подключает: это делает
клиент согласно настройке подключения при запуске.

При отмене разрешения подключение остаётся отключённым. Можно повторить попытку
или нажать **«Подключиться через Proxy»**. Эта кнопка включает сетевые настройки
приложения вместо YAML; Proxy передаёт трафик только программ, которые его используют.

## Если TUN не подключается

- **Предлагает переместить приложение.** Запускайте установленную копию из `/Applications`,
  а не из DMG, Downloads или временного каталога App Translocation.
- **Служба установлена, но недоступна.** Откройте настройки macOS → Основные →
  Объекты входа / Расширения (название зависит от версии) и проверьте, не отключена
  ли фоновая служба приложения. Затем в клиенте выберите
  **Настройки → Подключение → Восстановить службу** и подтвердите запрос macOS.
- **Нет прав администратора.** Для установки нужен администратор этого Mac.
  До установки можно пользоваться Proxy.
- **Ядро отвечает, но TUN не поднялся.** Клиент не считает это успешным подключением.
  Откройте «Журнал»: там доступны сообщения ядра, включая ошибки интерфейса, DNS
  и ограничений доступа к файлам. Экспорт журнала скрывает известные чувствительные данные;
  перед отправкой всё равно проверьте содержимое.
- **Не открываются домены.** В TUN на macOS приложение добавляет `dns-mode: native`,
  если профиль явно не задал другое значение. Это создаёт временную системную
  DNS-регистрацию, которая удаляется при завершении ядра. Явное `dns-mode: disabled`
  в профиле сохраняется; его нужно исправить в профиле или включить переопределение.
- **Профиль с локальными файлами.** Привилегированному ядру разрешено читать данные
  приложения и необходимые системные файлы. Локальные сертификаты и file-provider
  файлы должны лежать внутри каталога данных приложения; используйте абсолютный путь.
  Скачиваемые ресурсы и кеш TUN хранятся отдельно, в защищённом каталоге службы.
  Абсолютные пути для записи вне этого каталога не поддерживаются в TUN.
- **Конфликт сетевых программ.** Для диагностики отключите другое VPN-подключение.
  Если включён firewall и используется `mixed`/`system`, проверьте разрешение для ядра;
  также можно попробовать `gvisor` в настройках подключения.

После выхода из сна клиент заново подключает ранее активный TUN для обновления
маршрутов и DNS. Закрытие окна в трей сохраняет соединение; обычный выход отключает
его. Если процесс клиента аварийно завершился, служба отключает ядро после потери
связи с ним (примерно через 90–100 секунд). Это не аварийная блокировка всего интернета.

## Удаление

В клиенте откройте **Настройки → Подключение → Удалить службу** и подтвердите
запрос администратора. Туннель отключится, системная служба и её кеш будут удалены,
а профили и настройки клиента сохранятся. Затем можно удалить приложение из «Программ».
Удаление одного `.app` не удаляет ранее установленную LaunchDaemon.

## Для разработчиков и тестировщиков

- Служба устанавливается через `osascript` с `administrator privileges` и
  `launchctl bootstrap`, без Developer ID, `SMJobBless`, setuid и запуска Electron от root.
- Каждая пара UID/каталог данных имеет отдельную службу `com.cheezy.tun.<UID>.<ID>`;
  ID — первые 16 символов SHA256 канонического пути каталога данных.
- Файлы: `/Library/PrivilegedHelperTools/com.cheezy.tun/<UID>.<ID>/` и
  `/Library/LaunchDaemons/com.cheezy.tun.<UID>.<ID>.plist`.
- IPC: Unix-сокет `/var/run/cheezy-tun-<UID>.<ID>.sock`, права `0600` и проверка
  UID через `LOCAL_PEERCRED`. Это граница пользователя ОС: без Developer ID
  служба не подтверждает криптографически, что запрос отправлен именно нашим `.app`.
- API допускает статус, запуск фиксированного ядра, остановку и heartbeat.
  Замены программ, передачи командной строки и изменения разрешённых хешей через IPC нет.
- Ядро работает с root для TUN, с ограничениями файлового доступа и запуска программ
  через встроенный `sandbox-exec`. При невозможности применить ограничения запуск
  прекращается. Каталог кеша защищён от изменения обычным пользователем.
- `npm run dist:mac` собирает helper и включает его в приложение. Упаковка проверяет
  наличие Mach-O бинарников. Подпись ad-hoc не требует сертификата; notarization отключена.
- `npm run test:mac-helper` и обычные Go-тесты проверяют логику без установки службы.
  macOS CI дополнительно запускает `scripts/smoke-macos-tun.mjs` на выделенном runner:
  реальная установка, TUN/DNS, остановка, обновление и удаление. Не запускайте этот smoke
  на рабочем Mac: он временно меняет маршрутизацию тестовой машины.
- Windows-кросс-компиляция и имитация macOS не доказывают работу системных диалогов.
  Перед релизом проверьте скачанный DMG на чистом Mac: Gatekeeper, отказ/повтор выдачи
  разрешения, запуск TUN на Intel/Apple Silicon, сон/пробуждение, обновление, удаление.
